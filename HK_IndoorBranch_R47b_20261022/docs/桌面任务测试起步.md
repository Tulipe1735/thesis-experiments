# 室内桌面任务测试起步

本包已有 DH01-r10 的可视室内，以及独立 IN20 设备候选。学长可以新建房间或独立台面实验；仿真后端、机器人与控制接口由室内实验分支选择和接入，外围分支继续负责场景精修。

建议从一个桌面、少量可辨认道具和一个明确目标区开始。先在独立小场景确认物体尺寸、支撑接触、碰撞体、质量/摩擦参数和复位，再扩展到房内与跨房间任务。渲染网格不自动等于合适的物理碰撞体。

## 第一次可复现试验至少记录

- 共同场景基线SHA、室内增量SHA、任务版本和随机种子。
- 对象稳定ID、位置/四元数、速度、关节、可操作状态，以及哪些对象是静态背景。
- 桌面支持平面、可放置边界、机器人/相机坐标系和实际标定变换。
- 物理后端/版本、时间步长、重力、碰撞和接触参数；观测与动作的格式/单位。
- 成功/失败判据、超时规则、所有尝试的结果及失败类型。重复复位后检查初态是否一致。

`branch/TABLETOP_TASK.template.json` 与 `branch/EPISODE.template.json` 是待填写的记录结构，没有预设可运行控制器。空值表示尚未实现或测定，不能当作有效参数直接运行。

## 可以复用的历史材料

`legacy_physics_DH01r10` 有335项静态碰撞、10个铰链、13个道具的历史局部记录与既有 Rapier 实现。先把该目录复制到工作目录，再执行 `node verify_registered.mjs`；它会在自己的工作目录写验证结果。这是历史局部物理检查，不是新房间验证，更不是Agent任务成功结果。

旧适配把 Blender `(X,Y,Z)` 映射到 Rapier `(X,Z,−Y)`；只在对应适配边界使用，不要写回 `.blend` 城市坐标。IN20 的原生碰撞检查也只覆盖其记录中的对象和条件。

建议把脚本参考控制、遥操作和自主模型执行分开记录；保留失败试次。新增模型服务需要自行配置凭据，本包不包含服务器登录信息、API密钥或自动运行的Agent。
