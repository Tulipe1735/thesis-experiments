## 0. 一句话

Agent 在练习中，把做成的事积累为 artifact，节点之间用类型化的边组织成技能图。大脑通过图检索取用一小包相关技能；每个 artifact 有一组投影，从"大脑全程参与"到"纯代码执行"排成阶梯。三个过程分工如下：

- **Grow Up**：往图里加节点（叶子或组合）和有证据的边（积累算法 A）。主要来源是大脑自己的失败：失败后回到快照，在图中搜索、试替代、改组合，仍不行就写新叶子；所有产出在轮次结束后过证据门；
- **Root Down**：为每个 artifact 在每种情境下选用更省的投影，并证明新投影与原投影等价（投影算法 R）；
- **Revise**：用练习回放迭代 A 和 R 本身。

## 1. 核心对象

### 1.1 三层结构

| 层 | 内容 | 谁改 | 何时改 |
|---|---|---|---|
| 内核原语 K | 身体接口、感知原语、规划器、保护规则、独立评价器、大脑模型（§1.5） | 人 | 实验系列之间，发布为新的 K 版本 |
| 叶子 artifact | 源码，**只调用内核原语**，在隔离 Worker 中执行。例如定位、抓取 recipe、接近方式、放置目标、撤手 | Grow Up：主要由大脑在失败恢复中写出（§2.1.1）；Codex 或人写的记为外部作者，单独报告 | 回合内只在快照分叉中试用；轮次之间经证据门提交（§2.1） |
| 组合 artifact | 子 artifact 的有序序列，加上参数绑定和每一步的 `post` | Grow Up（从成功回合中抽取，包括恢复后成功的回合） | 轮次之间 |

初始图 **G0** 由旧 T03 线留下的叶子构成：`hand_open`、`t03_adaptive_recipe`、`t03_placement_target`、`t03_post_release_finish`，以及颜色定位和 `AdaptiveGrasp` 的阶段封装。候选叶子 `t03_observed_can_route` / `_pose`、`t03_locate_residual_consensus` 作为 `candidate` 节点导入，不默认开放。

### 1.2 Artifact 字段

| 字段 | 内容 |
|---|---|
| 签名 | 名称，以及类型化参数。参数是类别，例如 `obj: cup`、`dst: tray`，不是具体坐标 |
| 适用描述 | 一句"何时适用"的文字，加上从契约派生的关键词；只用于检索，不进入判定（借 SkillDAG 的节点描述、GoS 的能力摘要） |
| 契约 | `pre` / `post` 只能取自 `harness/contracts.py` 的封闭谓词集；另有失败码闭集 |
| 内容 | 叶子：源码的 SHA256 引用；组合：子 artifact 序列与参数绑定 |
| 统计 | 按情境桶（§1.4）记录：调用次数、成功率、成本、降级次数、最近使用时间 |
| 状态 | `candidate` → `validated` →（`demoted`）→ `retired`；对应 `contracts.DECISIONS` 中的 promote / reject / demote / retire |
| 谱系 | 来源回合、父版本、作者、来源类型 `origin`（`brain_recovery` / `triage` / `external_author` / `import`）；父版本只是来源，不是执行依赖 |

### 1.3 类型化技能图

**边的类型**

| 边 | 含义 | 怎么产生 | 证据 | 约束 | 借鉴 |
|---|---|---|---|---|---|
| **调用** A ⇒ B | 组合 A 的内容里调用了 B | 由组合内容直接得出 | 结构性 | 无环 | 原方案的能力树 |
| **衔接** A → B | A 的 `post` 满足 B 的 `pre` | 由契约自动计算，不手写 | 结构性；实测断开时另记冲突边 | 可以有环 | GoS 的 dep 边（I/O 兼容） |
| **特化** D ⊑ A \| b | D 与 A 契约相同，在情境桶 b 中 D 明显更好，应优先选 D | Grow Up 提出，经证据门提交 | 在 b 中从同一批快照做配对分叉，D 胜出达到门槛 | 无环 | SkillDAG `specializes`，这里加上按桶成立 |
| **替代** A ≈ B \| b | 契约相同，在 b 中成功率无显著差别 | 配对分叉结果不显著时记录 | 同上 | — | SkillDAG `similar_to`、GoS alt |
| **冲突** A ↛ B \| b | 衔接边按契约成立，但在 b 中实测 B 接在 A 之后反复失败 | 缺口记录（§2.1 第 9 步） | ≥m 次失败，并且有快照分叉复现 | 只用于剪枝和缺口定位 | SkillDAG `conflicts_with` |

与两篇论文的差别：
- SkillDAG 的 `composes_with` 在这里不记成边，而是直接生成一个组合节点；
- SkillDAG 的 `depends_on`（拿掉 B，A 的成功率下降）由调用边加衔接边表达，需要时用"拿掉 B 的分叉"验证。

**护栏**（借 SkillDAG）：
- 调用边和特化边无环；
- 同一对节点在同一个桶里，不能既有特化或替代边，又有冲突边；
- 所有提交只追加记录，记录来源（契约 / 证据 / 导入）、理由、任务 ID 和证据路径；
- 图按轮次冻结成包，可以整体回滚到任何一个冻结包。

**图的五种用途**

1. **取用**：大脑每次决策看到的是一小包技能，不是整张图，具体做法见下文。
2. **组合**：沿衔接边搜索出候选链，交给大脑确认；也可以从成功回合中抽取，变成组合节点。
3. **去重与合并**：见 §2.1。
4. **缺口定位**：失败时指出是哪条衔接边断了，或者哪个节点在哪个桶里失败。
5. **回归范围**：某个节点改动后，只重放沿调用边依赖它的祖先节点所在的历史任务。

**取用**（借 GoS 的"种子 + 反向扩散 + 按预算装载"）：
1. **种子**：选出 `post` 覆盖任务目标谓词的节点，再加上适用描述与任务文字匹配的节点。
2. **反向扩展**：沿衔接边和调用边逆向找前置节点，深度不超过 D。例如目标匹配到"放置"，就会把"抓取""定位"一起带出来。当前图只有几十个节点，用有界广度优先搜索就够了；节点数到几百以上，再换成 GoS 的反向感知 Personalized PageRank。
3. **剪枝与标注**：按当前桶用冲突边剪枝；用特化边标出"本桶优先"。
4. **装载**：在上下文预算内装载这些节点的 P2 调用卡。大脑另有两个图工具：
   - `show`：查看某个节点的完整步骤或源码；
   - `search`：按契约（`pre` / `post`）、情境桶和文字查询节点，返回契约相同或 `post` 覆盖目标的节点，附各桶统计和特化 / 替代 / 冲突标注。练习轮次中也返回 `candidate` 节点。失败恢复（§2.1.1）主要靠它。
5. **本轮内图冻结**：大脑可以在回合中提出节点或边，也可以在快照分叉里试用它们（包括自己刚写的叶子），但图本身不改；提议和试用结果只记入日志，轮次结束后才经证据门处理。这一点与 SkillDAG 的回合后立即提交不同。

任务树 D（`library/tree.yaml` 的 `nodes`、`T0_TASK_TAXONOMY.md`）只用于课程安排和报告维度。artifact 通过 `task_node` 关联到 D，可以多对多。**不按 D 的节点手工创建 artifact。**

### 1.4 投影阶梯

同一个 artifact 有四种投影，区别在于大脑参与多少：

| 投影 | 谁做选择 | 谁执行 | 怎么产生 | 现状 |
|---|---|---|---|---|
| **P3 模板** | 大脑逐步决定 | 大脑逐步调用子 artifact 和原语 | 创建时自动生成：契约、步骤、证据摘要 | 新增 |
| **P2 可调用 skill** | 大脑只决定"调用这张卡" | 代码 | 创建时生成调用卡：签名、适用描述、契约、证据 | 已有：`artifact_mapping` 的 skill 投影 |
| **P1 路由** | 查路由表（情境桶 → 节点） | 代码 | 只能由 Root Down 产生；特化边是主要来源 | 新增；`harness/router.py` 是雏形 |
| **P0 代码** | 不需要选择 | 代码，每一步之后检查监测谓词 | 只能由 Root Down 机械编译 | 已有：`artifact_mapping` 的 code 投影 |

叶子的 P0 就是它自己的源码；对叶子而言，投影阶梯主要体现在"大脑是否需要在同契约的几个叶子之间做选择"。

规则：
- 运行时，在当前情境桶中选用**已获准的最低一级投影**。任何监测谓词失败，都升回 P3，交给大脑处理；练习轮次中，大脑接管后进入失败驱动恢复（§2.1.1）。
- 相邻投影之间的等价，分两级定义：
  - **决策等价**：发出的子调用序列相同。在确定性仿真中，这意味着轨迹逐字节一致。
  - **效果等价**：结束状态的后置谓词相同，并且关键位姿在登记的容差之内。
- P0 由契约、子序列、路由和监测谓词直接翻译而来。**Root Down 不让 LLM 写新的控制代码**；叶子源码由 Grow Up 产生，并且必须经过证据门。

### 1.5 情境桶

情境桶是特化边、Root Down 和缺口统计的分组单位。它只用**大脑可见的合法观测**来计算，不用真值。T01–T04 的初版特征：

- 模板；
- 目标物类别（杯型 / 水果）以及可见颜色类别；
- 容器类别（托盘 / 果盘）；
- 容器中已占用的位数；
- 目标物近侧 r 范围内是否有非目标物；
- 位置单元。

**桶条件（第五版）**：上面六个特征全交叉有上千个格子，而每轮只有十几个训练实例，绝大多数格子里是 0–2 个实例。所以特化 / 替代 / 冲突边里的"| b"、止损的键、P1 路由项都不挂在完整格子上，而是挂在一个登记的桶条件上：
- 桶条件是至多两个特征取值的合取，例如"目标近侧 r 内有非目标物"，或"水果 ∧ 果盘"。候选提出时登记，登记后不改；要换条件就是新候选。
- 位置单元默认不进桶条件。测试的位置轴用的是训练中没出现过的格子，按位置成立的边和路由在测试时无法命中。
- 运行时一个状态可能满足多个桶条件：取已提交证据最多的那一条；都不满足就回到无条件的默认节点。
- 每条配对、每次调用都保存原始特征向量，不只存桶编号。Revise 改特征集或桶条件后，边、路由和位移账从原始记录重算，不靠新旧桶的映射估计；重算后证据不足的边转为 `pending`。

特征集本身属于投影算法 R 的一部分，可以被 Revise 修改。阶段 0 使用的"可达桶（near / far）"是按任务规范划分的测量分组，不是情境桶特征（见 GLOSSARY）。

### 1.6 内核 K

- **身体接口**：`plant.dispatch` 支持 `state`、`wait`、`set_joints`（左臂和左手，每次最多 14 个关节）；本体观测；头部 RGB-D。
- **感知与规划原语**：点云与支撑面拟合，即 `reuse_grasp` 中的基础函数；`ArmPlanner` 逆解与路径检查。
- **隔离执行**：`grow_up_v2/isolation/worker.py`，以及源码检查。
- **保护规则**：`grow_up_v2/plant.py` 的 `monitor`。
- **独立评价器**：`tabletop_predicates.py`、`t03_evaluator.py`，以及按评价器版本登记的边界测量口径。
- **大脑模型**：固定为同一个模型标识（当前是 DeepSeek，经 `harness/agent.py` 网关调用），整个实验系列内不换。
  - 托管模型在同一标识下可能被服务方更新，标识不变不等于模型不变（第五版）。每次调用保存服务方返回的模型名与版本指纹；每轮开跑前用一组登记的固定提示各调用一次，与系列开始时的回复比较。回复出现系统性变化时，把系列从这一轮切成两段分开报告，证据门配对不跨段累积。
  - 大脑输出本身不确定，所以凡是大脑参与的比较都不能用"重跑一次"当作确定性复核，只能当作一次重复（§2.1 第 6 步）。
- 一个实验系列内 K 冻结不变。K 的任何改动都发布为新的 K 版本，结果按版本分开报告，**不算作 Grow Up 的产出**。
- **改 harness，不改大脑推理**（Wang §7："what the agent learns is decided by the harness"）：大脑的模型标识、推理设置在系列内固定；进展来自 harness 一侧——评价器、证据门、记忆与尝试状态、提示文本、内核原语。harness 的任何改动（新 K 版本、评价器版本、门规则、提示文本）发布前，先在已记录的档案上重放，列出哪些过去的判定、提交或缺口归类会翻转及原因，随版本登记（借 D12）。
- 阶段 0 运行记录里的 `K_v1-20261113`，指的是"当前内核原语 + G0 叶子的固定工具链"。按本版的分层，其中的叶子部分属于 G0，不属于 K。
- **K_v2（第四版，Grow Up 首个实验系列使用）**：K_v1 加一个 VLM 定位原语，其余不变（契约与前提见 §5.4 K3）。
  - 它只是供叶子和大脑调用的感知原语：不参与任务判定，不替代独立评价器，本版也不用于计算情境桶特征。
  - 大脑模型不变。原语输出作为合法观测，与 RGB-D 同级。
  - G0 叶子不调用该原语，阶段 0 基线的数字对 K_v2 下的 G0 仍然适用；系列开始前在 K_v2 下复跑 G0 near 桶一次，确认决策等价后才沿用。

## 2. 三个过程的定义

### 2.1 Grow Up：往图里加节点和边（积累算法 A）

**时机**：在线，每个练习轮次。

**输入**：本轮的练习实例；冻结的图 G_r；内核 K_v。

**输出**：候选节点（叶子或组合）；候选边；恢复记录；证据门结果；合并和晋升记录；能力缺口记录；决策日志与快照。

**本轮内 G 不变。**

步骤：

1. **执行**：大脑按 §1.3 取用技能包，在 P3 下调用已有 artifact（按 §1.4 选投影）。每个 artifact 边界保存快照，每次大脑决策写一条日志，包括大脑在回合中提出的节点或边。
2. **失败驱动恢复**：某个节点失败时，大脑回到该节点的入口快照，自己搜索、试替代、改组合、写新叶子，见 §2.1.1。恢复成功就从成功的分支继续执行回合。
3. **抽取组合**：只从成功回合中抽取，包括恢复后成功的回合（用恢复成功的那条分支）。取两次后置谓词成立之间的子调用序列，把具体实体抽象成类别参数，生成候选组合节点的 P3 和 P2。恢复成功的分支可能用到本轮刚写、尚未提交的叶子；这样抽出的组合，状态不能高于它引用的任何子节点：子叶子在证据门上未定时组合保持 `candidate`，子叶子被拒绝时组合一并拒绝并记录原因。
4. **收集叶子**：
   - 主要来源是第 2 步中大脑写出、并在快照分叉里至少成功过一次的叶子，`origin = brain_recovery`。
   - 兜底来源：缺口记录（第 9 步）指向的叶子缺口，由离线分诊（§6）或外部作者（Codex、人）补写，`origin` 分别记为 `triage` / `external_author`，单独报告。
   - 两种来源都必须满足：契约与原叶子相同（变体），或者给出新契约；源码只调用内核原语，通过源码检查，在 Worker 中执行。
5. **契约检查**：候选的每一步 `post`，都要在记录轨迹对应的快照上求值为真。不满足就不进入证据门。
6. **证据门**（配对分叉）：
   - **对象**：变体叶子，以及候选的特化、替代、冲突边。
   - **做法**：从原节点在桶条件 b（§1.5）下的边界快照抽取（入口状态库启用后从库中抽取，§2.1.3），从同一批快照分别执行原节点和候选节点，按两个口径配对比较：本节点 `post`（及已实现的交接证据），以及最终任务结果。
   - **分叉从候选的生效点起跑（第五版）**：有的叶子在所属节点入口之前就已经生效。现有实现里，抓取 recipe 和手部阻抗在回合配置时绑定（`harness/kernel.py` 的 `recipe_binding`），从 grasp 入口检查点续跑会沿用旧绑定，换了 recipe 叶子也不起作用。每类叶子登记它的生效点；配对和恢复分叉都从生效点的检查点起跑，recipe 类从 `00_configured` 起跑。从更晚的检查点起跑、候选改动没有被执行的配对，记为不可分辨。
   - **快照按登记规则抽取，不按原节点成败挑着用**。恢复时用的失败快照上，原节点必然失败；只用这些快照会系统性高估候选。所以恢复分叉只作为"恢复证据"记录，不计入配对。下面的分层是把成败两层都按规则抽出来分别检验，不是只留一层。
   - **n 按不同实例计**：同一实例只取一个快照（按实例与状态哈希去重）；候选作者在恢复或诊断中见过的实例，不进该候选的配对。
   - **只用 Agent 来源的配对决定提交**：工程栏来源的配对只用于检出和报告，不参与胜负计数（§2.1.3）。
   - **分层抽取（第五版）**：快照按原节点在该快照上的记录结果分成失败层和成功层，两层都按登记规则抽，层内不挑。失败层用来看候选能不能修好，成功层用来看候选会不会弄坏本来能做的；两层都要有，才回应了上一条"只用失败快照会高估"的问题。两臂都不含大脑决策时（P0 / P2 固定调用），原节点一臂直接取已记录的结果，不重跑，分叉预算只花在候选一臂。
   - **提交条件（第五版，替换第四版的"至少 n 对、净胜 ≥ δ"）**：以本节点 `post` 口径计胜负，同时满足三项才提交特化边：
     1. 修复：失败层净胜（胜减负）≥ δ；
     2. 无害：成功层至少 n_s 个可评估实例，落败数不超过登记的 h_max；
     3. 任务口径不反对：在任务结果可分辨的配对上，候选净胜 ≥ 0。本节点口径胜出、任务口径净负的候选拒绝，并写入冲突线索（候选让本节点通过，却让下游更差）。
   - **三种结局与配对上限**：每个候选登记配对上限 N_max（两层合计的可评估实例数）。达到提交条件即提交；失败层净胜 ≤ −δ，或成功层落败超过 h_max，即拒绝；到 N_max 两者都没达到，记为 `pending`（未定），不再加配对，除非原节点、候选、K 或评价器有变化。配对可以跨轮累积，但只累积到 N_max 为止。第四版没有上限：对一个与原节点无差别的候选，一直加配对直到净胜够数，迟早会提交。
   - **替代边只在有证据时写**：到 N_max 且两层净胜的绝对值都 ≤ 1，才记为替代边。配对不足时一律是 `pending`，不写成替代。"没测出差别"和"测过、确实差不多"是两件事，Root Down 的路由只应该依据后者。
   - 两臂结果相同、且都没有执行到候选改动部分的配对，记为不可分辨，不计入任何一层。
   - **差异须重复**：大脑在 P3 参与的配对中，两臂结果不同的，再跑一次（两臂都跑）。两次方向一致才计一次胜或负；不一致的记为不可分辨。大脑输出不确定，这一步是重复，不是确定性复核。
   - **初值的含义要写在登记里**：n_s=4、h_max=0 时，"无害"只能排除候选在成功层有一半以上落败的情形，是很弱的保证；候选提交后仍靠 Root Down 的降级和回归把关（§2.2）。δ、N_max、n_s、h_max 的初值见 §5.5，开跑前按当轮各桶条件的实例数算一遍：凑不满的桶条件，候选直接记 `untestable`，不开分叉。
   - 分叉回合计入轮次预算，与练习回合、恢复分叉分开报告。
   - 这一步回应了 SkillDAG 自述的局限："单次观察就提交边"缺少统计门槛。
7. **去重与合并**：签名和 pre/post 与已有节点相同（参数抽象之后）时，只给已有节点增加证据；子序列不同、契约相同时，作为同一节点的另一种实现记录下来，或者走证据门变成替代或特化边。
8. **晋升**：候选要在**之后的轮次中被实际调用**，才有资格转为 `validated`。仅仅是同一模式在多个实例中重复出现，不算数。
   - **晋升窗口（第五版）**：第四版写"在 m 个不同实例上 `post` 全部成立"，没有说从哪次调用算起，也没有说失败一次之后怎么办。改为：取提交后的前 W 次实际调用（按不同实例计），其中 `post` 成立的实例数 ≥ m，且成立比例不低于原节点在同一桶条件下的记录比例，转为 `validated`；W 次用完仍不满足，转为 `demoted`，不再重新计数。
   - 候选只在练习轮次的 `search` 结果里出现，大脑可能一直不选它，W 次调用永远凑不满。每轮报告各候选的被调用次数；连续 c 轮为 0 的候选，下一轮在它的桶条件下由调度指定调用一次，这类调用标为"指定调用"，不算大脑自主选用。
9. **缺口**：大脑在恢复预算内搜索过、扩展过仍然失败，才把这次失败计入缺口统计。同一节点、同一情境桶反复如此（≥2 个模板，或者同一模板 ≥m 次）时，写一条能力缺口记录，并按 §6 分诊。
   - 恢复、证据门与分诊中的每次尝试都写闭集**尝试状态**：`refuted`（实测否定）、`candidate_invalid`（候选自身不合规：源码检查不过、候选代码异常或超时）、`untestable`（不可测，例如没有可用快照）、`infra_failed`（harness 自身失败：Worker 启动、仿真器、网关等）、`pending`、`never_run`。
   - **分叉预算耗尽不算否定（第五版）**：现有检查点续跑时，仿真秒数和命令数预算从源回合继承，只有墙钟重新计时（`harness/kernel.py` 的 `execute`）。从靠后的检查点分叉，剩余预算可能不够跑完这个节点。恢复分叉和证据门分叉各自登记"从入口到本节点结束"的预算，不继承源回合的余量；分叉因预算或墙钟超时而结束时记 `untestable`，不记 `refuted`，也不记 `candidate_invalid`（候选代码自身死循环导致的 Worker 超时仍是 `candidate_invalid`）。
   - 只有 `refuted` 计入缺口统计。`refuted` 与 `candidate_invalid` 都计入位移账（§2.1.2），后者不算"假设被否定"。每条状态标评价器版本与 K 版本；版本变化后，旧的 `refuted` 转为 `pending`，不再作为否定证据。
   - 大脑拒绝修改并给出理由时，原文记入缺口记录的"判定缺口线索"，供人检查评价器与保护规则。

#### 2.1.1 失败驱动恢复（回合内，大脑主导）

这是 Grow Up 的主要生长来源：能力由操纵机器人的大脑在自己失败之后长出来，而不是由外部流程替它补。

**触发**：某个节点的 `post` 不成立、监测谓词失败，或者保护规则触发。记录失败码、情境桶和该节点的入口快照 ID。

**大脑的恢复步骤**（每一步都从入口快照分叉执行，结果写入日志）：

1. **诊断**：读失败码、合法观测和该节点的调用卡；需要时 `show` 查看源码。
   - **评价器可达性试跑**（借 Wang §6："the evaluator can run its own reach trial before judging a motion"）：节点失败后，评价器侧从该节点的入口快照起跑一次该步的参照执行，看这一步从这里是否做得到。试跑结果大脑不可见，不计入任何栏的成功，分叉回合计入轮次预算并单列。
   - **现状（第五版，2026-11-15）**：`harness/reach_trial.py` 已实现，参照执行是 K_v1 同一阶段代码，**不用真值**（第四版写"允许使用特权真值"，与实现不符，以实现为准；要改成用真值的参照，属于新的评价器版本）。E2 检查 `outputs/tabletop_reach_trials_20261115_002/summary.json`：69 次试跑全部与源回合一致，归因全部是 `untestable`，因为失败的执行者就是参照本身，试跑只是重放。所以在 Agent 栏执行器存在之前，这一机制不产生任何归因；校准也要等非参照执行者在同一入口上实际通过过才有样本。
   - **参照本身通不过的节点，试跑没有判别力**：阶段 0 中 TP03 的 `01_grasp_preflight` 是 0/3，TP01 的 `04_grasp_approach` 是 1/3。在这些节点上参照几乎总是失败，试跑会把几乎所有失败都指向上游。校准规则（假"不可达"率上限、最少试跑数）按节点启用，正是为了挡住这种情形；没启用的节点，失败留在本节点，不上移。
   - **试跑结果改变大脑的恢复目标，是一种辅助**：大脑看不到试跑结果，但"改从上游节点恢复"这个指令本身带着信息。启用后，Agent 栏的恢复后成功注明"经评价器试跑归因"，与未经归因的分开计数。
   - 试跑也失败，记为"入口不可达（试跑）"：恢复目标改为产生这个入口的上游节点，失败归到上游；原始 p_j 与归因后 p_j 并排报告，失败不从训练分母中移除；回溯到链起点的记为内核缺口。试跑成功，说明这一步本身可做，按原节点恢复。
   - 不用运动学检查代替试跑：当前 `ArmPlanner` 逆解与路径检查不含环境碰撞（`environment_collision_checked=False`），`t03_handoff.HANDOFF` 字段只有声明；这些只作日志标注。
   - **启用条件**：快照完整性满足（§2.1.3），并在已有回合上登记校准——在实际成功过的入口上，试跑失败的比例（假"不可达"率）不超过登记值。参照执行本身是固定工具，它做不到的步骤不能据此判定为上游原因，这类情形记为 `untestable`。
2. **搜索已有节点**：用 `search` 查契约相同、或 `post` 覆盖当前子目标的节点，参考特化 / 替代 / 冲突标注和各桶统计，选一个试。成立就是"选择缺口"已在回合内解决。
3. **改组合**：重排步骤，或在失败节点前后增加已有节点（例如先撤手再换方向接近），从快照试。
4. **扩展**：前两步都不行，大脑写一个变体叶子（与原节点契约相同）或新契约的叶子，过源码检查后在 Worker 中从快照试；可以在预算内迭代修改。已被叶子止损（§2.1.2）关闭的键，在关闭期内不能再写同契约变体，只能走第 2、3 步；新契约的叶子要先过证据门，才算新键。
5. **放弃**：恢复预算用完仍不成立，这一回合按失败记录，转入第 9 步的缺口统计。

**规则**：
- **回到快照是仿真特权**。只在练习轮次中允许；冻结测试中禁用，失败就按失败计，只能从当前物理状态继续调用图中已有节点，不能写新叶子。报告中注明这一区别。
- **恢复预算**单列：每个实例的恢复分叉数和恢复中的大脑调用数各设上限（§5.5），与练习回合、证据门分叉分开计数。用完就停，不在同一实例上反复修（§5.2）。
- **图不改**：恢复中试用的节点和新写的叶子只存在于分叉里，按 §1.3 第 5 条记入日志；轮次结束后才经第 4–6 步处理。
- **成功分栏**：经恢复才成功的回合在 Agent 栏单列为"恢复后成功"，注明恢复次数、分叉数和是否用到新写的叶子；不与一次通过的成功合并。
- **归因**：每个候选的 `origin` 写明是大脑恢复产出（`brain_recovery`）还是分诊或外部作者产出。只有 `brain_recovery` 可以写成"大脑自己长出的能力"。

#### 2.1.2 叶子止损（位移账）

**问题**：可改的底层是叶子源码。某个缺口实际缺的是语义或感知能力时，大脑（或外部作者）可能把它写成越来越多的数值规则，只在见过失败的状态上成立，形成语义位移。第 4 步本身不限制次数，这是"在同一片叶子上反复修"的入口之一。另一种情形是变体其实有效，但失败转移到了下游；两者要分开处理。

**适用范围**：关闭动作先只用于感知与语义类键（定位、识别、消歧）。几何与接触类键（如 F1、F3、F4）只记账、报告触发情况，不关闭；等 A_ours−止损 消融有结果再决定是否扩大。依据：Wang 的位移证据只来自关系感知一个前线，该文 Table 2 对抓取保持和可达性的可表达条件都标为成立。

**键**：（节点契约，桶条件，失败码）。第四版用缺口 ID 作键的一部分，但缺口记录要到失败反复出现之后才写（§2.1 第 9 步），在那之前写出的变体无键可记；同一个缺口 ID 下也可能混着两种机制（例如同是"抓取在近邻桶失败"，一种是手指擦到罐子，一种是拇指超速）。失败码取自契约的失败码闭集，变体写出时就有。缺口记录写出后再把键挂到缺口 ID 上。改契约要先经证据门才算新键，避免改一个谓词就绕开关闭。Revise 修改特征集或桶条件时，账本从保存的原始特征向量重算（§1.5）。

**哪些键算感知与语义类**：不靠逐个判断，按节点契约登记——`post` 只含定位、识别、消歧类谓词的节点，它的键属于这一类；清单随轮次登记，系列内不改。

**账本**：轮次结束后按键记录：
- 该键下的全部变体，分 `origin` 记录；触发只用 `origin = brain_recovery` 的变体，分诊和外部作者的变体单独报告；
- 每个变体在证据门上按两个口径（本节点 `post`、任务结果）的胜、负、不可分辨数；
- 每个变体的尝试状态（`refuted`、`candidate_invalid` 计入）；
- 每个变体的参数总数（源码数值字面量加组合中的参数绑定），只作报告，不作触发，因为容易被改写方式绕开。

**触发**（任一项成立）：
1. 同一键已有 ≥s 个变体，每个都有 ≥e 个可评估实例（改动已执行、本节点 `post` 可求值），且按本节点 `post` 口径净胜（胜减负）≤ 0；
2. **状态拟合**：同一键至少有 3 个原节点也失败、失败码相同的记录状态（来自不同实例）；某个变体在其中一个上成立，在其余兄弟失败状态上**实际执行过**且一次也没有成立。只与兄弟失败状态比较，不与原节点本来就成功、或分支不触发的状态比较。第四版的门槛是两个状态：修好两个中的一个就触发，而这可能是一个修复率一半的真改进。在兄弟状态上执行变体要花分叉，计入证据门分叉预算并单列；没执行过的兄弟状态不算"没有成立"；
3. **反复不成**：同一键 `refuted` 与 `candidate_invalid` 的变体合计 ≥t，且没有一个在证据门上净胜 > 0。

**失败下移不触发止损**：变体执行后本节点 `post` 成立、而任务在下游节点失败时，按本节点口径记为胜出，不计入触发 1。它是"转向下游"的信号：下一轮该下游节点的候选优先分到证据门预算（§2.1.3）。

**失败下移要排除候选自己造成的下游失败（第五版）**：只有同一快照上原节点一臂的任务也没有成功时，才记为失败下移。原节点一臂任务成功、候选一臂在下游失败，是候选弄坏了下游（例如换了一种抓法，本节点通过，却放不进去），按任务口径记为落败，进入证据门的第 3 项条件（§2.1 第 6 步），不产生"转向下游"的信号。

**关闭期间这个键上的实例照常调度**：它们仍在训练分母里，仍按登记的比例被选中，失败照常记录；不因为键已关闭就少排。这部分回合换不来新信息，是止损的成本，随 A_ours−止损 消融一起报告。

**动作**：
- 关闭该键 c 轮：第 4 步不能再写同契约变体，兜底的分诊和外部作者也不补该键的变体。`search` 和改组合照常可用；该键已提交的变体照常晋升、降级。
- 该键的能力缺口改判为**表达缺口**，写明候选去向：改契约或拆分节点，交给组合解决；或需要新原语、新的感知模型类别，转为内核缺口，在实验系列之间做。
- c 轮到期后，若已积累到 ≥e 个此前未用过的兄弟失败状态，就重新开放并复核一次；K 版本变化、或经证据门的契约变化，也重新开放。关闭不是永久否定。
- 告知大脑哪些键已关闭的提示文本，登记为 A 的一部分；消融两臂用同一段文本，只差关闭清单是否生效（Wang 记录到一段提示文字就能让修改率从 0/8 变到 11/12）。

**依据与边界**：Wang（§9）的长跑里，同一个两状态缺口试了 27 次，一个状态每次都救回、另一个从未救回，区域技能长到 33 个阈值、约三千行仍不收敛。该文据此提出位移检测与升级（D5），但作者没有检验这一建议；"更强的修复者位移更快"在该文中是论断，不是测量。本节因此作为假设登记，由 A_ours−止损 消融检验。

#### 2.1.3 阶段入口状态库（抵消前沿锁定）

**问题**：任务成功 S = ∏ p_j。第 j 步的改进 Δp_j 对任务的贡献是 π_j · Δp_j · ∏_{i>j} p_i：被到达率 π_j = ∏_{i<j} p_i 打折，也被后续各步的条件成功率打折；它的可测性被 π_j 打折。证据门若只用本轮自然走到 j 的快照，下游节点的配对很少，失败和候选都堆在最早失败的节点上（前沿锁定）。后一项也说明：下游未修好时，上游真实改进在任务口径上会表现为平局。

**启用前提**（未满足前，证据门仍用本轮边界快照，但按 §2.1 第 6 步去重和计数）：
- **节点粒度**（第五版按现状改写）：`harness/kernel.py` 现在每个阶段边界都写检查点（locate，grasp 内的 preflight / prepare / preflight / approach / close_and_test / lift_and_hold，place 内的 transfer / lower / release_and_retreat），approach 已有独立入口。
- **快照完整性**（第五版按现状改写）：检查点含 MuJoCo 积分状态、plant / port / 控制器的属性和工具链记录。E1 验收 23/23 次续跑与源回合逐字节一致（`outputs/tabletop_checkpoint_check_20261114_001/checkpoint_check.json`）。这只对**工程栏固定链**成立；大脑在 P3 下执行的回合有自己的状态（技能包、对话历史、大脑提出的节点），Agent 栏执行器实现后要再做一次同样的验收，才算对 Agent 来源的快照成立。
- **检查点绑定代码**：检查点是控制器对象属性的 pickle，表头只比对格式、K 版本、任务和模板。harness 或控制器类改了而 K 版本没变时，旧检查点可能照常加载、行为却不同。跨轮复用入口库之前，每轮抽一条旧检查点重放，与原记录逐字节一致才复用；不一致就整库按版本变化处理。
- 每条快照标 K 版本与评价器版本；版本变化后旧快照不再入选。K_v1 换到 K_v2 时，阶段 0 的全部检查点因此作废，§1.6 的"K_v2 下复跑 G0 near 桶"同时负责重建入口库。

**规则**：
- 每个节点维护入口快照库。来源：Agent 栏练习回合、恢复成功的分支、工程栏回合（`engineering_column` 基线）、证据门分叉。每条快照标来源、情境桶、所属实例和状态哈希。
- 只收物理上实际走到、且该节点 `pre` 成立的快照；不传送物体或手工构造状态（Wang 的 D7 允许重置仿真器越过前沿，本文不这样做，以保持评价器口径与真实到达状态一致）。
- 证据门从库中按登记规则抽取（§2.1 第 6 步）：按实例去重，排除候选作者见过的实例；**只有 Agent 来源的配对决定提交**。工程栏来源的配对只用于检出下游效果，单独报告；依据工程配对检出、而 Agent 配对不足以提交的候选，记为 `pending`。
- 证据门分叉预算按各候选凑满 n 个可评估实例所需的量分配，不按失败次数分配；"失败下移"信号（§2.1.2）指向的下游节点优先。配对在原节点、候选、K 与评价器都未变化时可以跨轮累积。
- 负对照判废的批次，其快照从库中移除。用到这些快照的配对一并作废；已提交的边在去掉这些配对后重新按 §2.1 第 6 步判定，不再满足的在提交日志里追加一条撤销记录，由它产生的 P1 路由项撤下（第五版）。
- **下游库可能一直是空的**：阶段 0 没有任何回合到达托盘放置，果盘放置只到达 1 次。不传送物体，就只能等上游修好之后才有下游快照；在那之前，下游节点的候选一律 `untestable`，检查点起步练习也无从起步。这是本设计接受的代价，执行顺序见 §5.2 阶段 0.5。
- 某节点库为空时，它的候选尝试状态记为 `untestable`，不计否定；下一轮登记时说明靠哪种来源补齐。
- 每轮报告各节点的 π_j、p_j（Agent 栏、工程栏分开）和可评估实例数。
- **检查点起步练习**：除完整任务回合外，练习轮次可以从入口库中下游节点的快照起步，让下游技能拿到练习，而不只是等完整回合走到那里。每轮登记两类回合的预算比例；检查点起步回合在 Agent 栏单列为"检查点起步"，不计入完整任务成功，也不改变冻结测试从初态起跑的规则（冻结测试不回退快照）。

**积累算法 A 的可调参数**：分段规则、抽象规则、恢复预算与恢复步骤的顺序、提出叶子的触发条件、证据门的 δ / N_max / n_s / h_max 与桶条件、m 与晋升窗口 W、合并规则、淘汰窗口、止损的 s / e / t / c 与适用范围、告知关闭的提示文本、入口库的抽取与预算分配规则。

**对照组**（同一 K、同一批实例、同一预算）：

| 对照 | 做法 | 来源 |
|---|---|---|
| A_static | 图固定为 G0 加契约衔接边，不长节点，不改边 | GoS（静态离线图） |
| A_single | 节点固定；大脑在回合后凭单次执行结果提交或修改边 | SkillDAG（单次观察即提交） |
| A_voyager | 单次成功即把组合入库，不合并，没有类型化边 | Voyager |
| A_ours−恢复 | 与 A_ours 相同，但失败即结束回合，不回快照；叶子只由离线分诊和外部作者补 | 消融：衡量大脑失败驱动恢复本身的贡献 |
| A_ours−止损 | 与 A_ours 相同（含同一段提示文本），但 §2.1.2 的关闭不生效，只记账 | 消融：叶子止损 |
| A_ours−入口库 | 与 A_ours 相同（含同一预算分配规则），但证据门只用本轮自然走到的边界快照 | 消融：阶段入口状态库（单因素） |
| A_ours | 大脑失败后回快照搜索、改组合、写叶子；叶子和组合都可以生长；边经配对分叉证据门提交；特化边按桶成立；感知与语义类键受叶子止损约束；入口库满足启用前提后启用 | 本文 |

**对照的执行顺序与可比性（第五版）**：

- **先试点，再对照**：先只跑 A_ours 一次独立运行若干轮。目的是确认各机制实际发生：恢复触发、候选进入证据门、止损记账、入口库有货。第四版要求 7 臂 × 3 次独立运行同时开，按 §5.5 模板的预算、每个模板 8 个实例（阶段 0 的规模）计，每轮每臂是 16 个实例 ×（2 个练习回合 + 至多 6 个恢复分叉）+ 24 个证据门分叉，再乘 21；仿真很便宜（阶段 0 的工程回合墙钟中位数约 2 秒），贵的是大脑调用，每轮上限约 16 ×（20 + 10）× 21 ≈ 一万次。机制没发生之前花这笔预算，换不来比较。
- **消融按触发数开启**：某项机制在试点账本里的触发数达到登记的下限，才开它的消融臂；达不到就报告"未能检验"，不跑。止损尤其如此：阶段 1 唯一的感知类键是 F2，而 F2 预期由 K3 解决，关系查询键要到 TP05 / TP06 才出现。旧 T03 线"连续零触发就换焦点"的教训在这里同样适用。
- **固定实例日程**：各臂的图一旦不同，前沿规则给各臂选的实例、开放模板的时间都会不同（A_static 没有组合节点可以晋升，TP05 永远不开放）。对照块不用前沿规则调度，改用开跑前登记的固定日程：每轮哪些实例、哪一轮开放哪个模板，各臂相同。前沿规则只用于试点和对照之外的练习。各臂"按前沿规则本来会在第几轮开放"作为结果报告。
- **独立运行之间共用实例**：同一臂的 3 次独立运行、不同臂之间都用同一批生成实例，按已强制的种子规则登记为 `replicates`，`generate` 保持一致。差别只来自大脑输出和各臂规则。

两项新消融的预测与证伪（开跑前随轮次登记；大脑输出不确定，每臂至少 3 次独立运行，预算登记）：
- **止损**：指标按**缺口**统计，跨键汇总：每个缺口的变体总数、恢复与证据门预算总消耗、关闭后经组合或内核路线得到解决的比例。预测 A_ours 每个缺口的预算消耗更少、完整任务成功率不降。证伪：A_ours 成功率更低；或 A_ours 中被关闭的键，在 A_ours−止损 中由后续变体通过证据门并在之后的轮次晋升。
- **入口库**：植入一个已知有效的下游改动（开跑前登记其来源与已有证据），比较两臂对它的检出率与各下游节点的可评估实例数。预测 A_ours 检出率与可评估实例数都更高。证伪：两项都不更高。下游 p_j 与完整任务成功率并报，但不作为入口库的证伪条件（见 §2.1.3 关于后续打折的说明）。
- 两项消融检验的是本文的规则，不等同于 Wang 的 D5（换模型类别）与 D7（重置仿真器越过前沿）。

### 2.2 Root Down：为 artifact 选投影（投影算法 R）

**时机**：离线，每轮结束之后。

**输入**：决策日志、快照、G_r，以及本轮新提交的边。

**输出**：G_{r+1}（投影层级、路由、编译代码有变化），或者回滚记录。

| 算子 | 触发条件 | 产出 |
|---|---|---|
| 特化 → P1 | 特化边 D ⊑ A \| b 已提交，且 D 在 b 中为 `validated` | 路由项 b → D，大脑不再需要在 A、D 之间选择 |
| P2/P3 → P1 | 某 artifact 在桶 b 中派发次数 ≥k，且大脑的选择一致率 ≥p | 路由项 |
| P1 → P0 | 在 b 中展开序列固定，并且每一步都有可求值的 `post` | 机械编译出的代码，加上监测谓词 |
| 降级 | 监测失败率 ≥d | 退回上一级投影；特化边保留，路由项撤下 |
| 遗忘 | 路由项超过过期窗口未使用 | 删除该路由项 |

**验收**：
1. 对新投影覆盖到的历史情境，从快照出发重放。先检查决策等价；不满足再检查效果等价；仍不满足，就放弃这一项下放。
2. 对受影响子图（§1.3 用途 5）中的历史任务做回归，最多 30 个。
   - **回滚判据（第五版，替换"成功率下降就回滚"）**：逐任务配对比较新旧图包在同一保存初态上的结果。新图包落败数减胜出数 ≥ 登记的回滚余量 g，才整体回滚到上一个冻结的图包。当前完整任务成功率在 0/7 到 1/8 之间，大脑输出又不确定，只比两个成功率的话，1/8 变 0/8 就会回滚，而这在重复运行之间本来就会发生。
   - 新旧图包决策等价的任务，结果必然相同，不必执行，直接记为平局；回归预算只花在决策不同的任务上。
   - 另跑一组"旧图包对旧图包"的重复作为噪声底线；g 的初值不小于噪声底线里观察到的落败减胜出的最大值。

**投影算法 R 的可调参数**：k、p、d、过期窗口、情境桶特征、P2 调用卡的写法、监测谓词的选择规则、取用参数（扩展深度 D、上下文预算、种子规则）。

### 2.3 Revise：迭代 A 与 R（方法层）

A 和 R 写成 `library/policies/` 下的版本化代码，本身也是 artifact，用同一套冻结与回滚机制管理。

**时机**：每 N 轮一次，以及开放新模板层级时。前 3 轮不做 Revise，先积累数据。

步骤：

1. 把练习史 E 按时间切成开发组和打分组，打分组是最近的轮次。
2. 生成 M 个候选版本：
   - 阶段一：人工写参数网格；
   - 阶段二：模型读开发组的回放结果，连续写 M 个版本，每一版的结果反馈给下一版。
3. 回放评估：
   - **R 用一致性回放**：按时间顺序重走决策日志。候选 R 在每个 Root Down 时点，只能使用此前的记录。新投影的输出与当时的记录一致，就直接取记录结果；不一致，就从快照分叉重新执行。
   - **A 的回放分两部分**：证据门参数（δ、N_max、n_s、h_max）可以在已保存的配对分叉结果上精确重算"会提交哪些边"；其余部分一变，图就变，大脑行为也会跟着变，只能评离线指标（重复节点数、对已记录成功子序列的覆盖、预测的复用次数），必须用在线结果确认。
4. 在打分组上选出得分最高的版本。现行版本参与比较；另跑一组同策略分叉，作为噪声底线。
5. 新版本运行下一轮。在线结果与回放预测方向相反时回滚。核心报告项是"预测与在线是否同向"。

练习调度（选哪些实例、并行多少）在 T01–T04 阶段使用固定规则（§5.2），暂不纳入 Revise。

## 3. 一个轮次的迭代流程

```text
[轮次 r]  冻结 G_r、K_v；登记：对照组、预算、预测、证伪条件、本轮实例
   │
 ① 调度：按 §5.2 的前沿规则，从训练实例中选出本轮实例
   │
 ② Grow Up：逐个实例执行（取用 → 执行）；负对照照常跑
      节点失败 → 评价器可达性试跑（不可达则改回上游节点）
               → 大脑回到入口快照：诊断 → search → 改组合 → 写叶子
                 （限恢复预算；关闭期内的键不写同契约变体）
      回合证据：verdict / 决策日志 / 节点边界快照 / 恢复分叉 / 回合内提议 / 尝试状态
      → 抽取组合 → 收集叶子 → 契约检查 → 证据门（按实例去重、只用 Agent 配对决定提交）
      → 去重合并 → 晋升判定 → 写缺口记录（只计 refuted）→ 更新位移账、判定止损或失败下移
   │
 ③ Root Down：特化 → P1；统计 → P1 / P0 → 等价重放 → 子图回归
      → 通过就冻结为 G_{r+1}；不通过就回滚到 G_r
   │
 ④ 每 N 轮：Revise（A、R），新版本从下一轮开始生效
   │
 ⑤ 报告：两栏成功、投影占比、成本、图变化（节点 / 各类边）、缺口；不新建报告文件
```

**一轮分三个批次（第五版）**：按已强制的生命周期规则，回合开始后中断，整批作废、不重跑。一轮若只是一个批次，证据门的一个分叉中断，会把本轮的练习回合、恢复记录一起作废。所以一轮登记一次，但分成三个各自排他创建的批次，各有自己的事件日志和负对照：

| 批次 | 内容 | 作废时的后果 |
|---|---|---|
| 练习 | 完整回合、恢复分叉、可达性试跑 | 本轮没有候选，图不变，G_{r+1} = G_r；实例记为已消耗 |
| 证据门 | 配对分叉、止损触发 2 的兄弟状态分叉 | 本批配对全部作废，不进累积；候选保持 `pending`，下一轮用未见过的实例重新配对 |
| Root Down | 等价重放、子图回归 | 本轮不下放，图只含已提交的边 |

练习批次作废后不补跑同一批实例；下一轮按登记换新实例。三个批次的预测与证伪仍在同一份轮次登记里，开跑前写好。

每轮的输出放在 `outputs/<run>/`（每个批次一个子目录）：

- `config.json`、`registration.json`：本轮配置与登记；
- `graph_before.json` / `graph_after.json`：冻结的图包，含节点、各类边、提交日志；
- `episodes/<id>/`：`result.json`、`verdict.json`、`decision_log.jsonl`、快照；
- `recoveries/<episode_id>/`：失败驱动恢复的每次分叉，含入口快照 ID、尝试内容（所选节点、改后的组合或新叶子源码哈希）与结果；
- `forks/`：证据门的配对分叉回合；
- `candidates/`、`edges.jsonl`、`gaps.json`、`rootdown.json`：候选、边提交、缺口（含位移账与止损记录）、下放记录；
- `entry_library.json`：各节点入口快照的索引（快照 ID、来源、情境桶、实例），快照本身仍在 `episodes/` 与 `recoveries/` 下。

旧的 `runs/` 只读。

### 5.6 T01–T04 阶段的完成判据

## 6. 卡住时：分诊

**第一责任人是大脑**：练习轮次中，失败先由大脑按 §2.1.1 在回合内处理，前三类缺口大多在那里解决。下表同时用于两件事：给大脑的恢复结果归类，以及处理恢复失败后留下的缺口记录。

| 结果 | 归类 | 回合内（大脑恢复） | 恢复失败之后（兜底） |
|---|---|---|---|
| 某个已有节点能让 `post` 成立 | 选择缺口 | `search` 找到并在快照分叉中成立 | 证据门提交特化边，Root Down 下放为 P1 |
| 改变顺序或增加步骤后能成立 | 组合缺口 | 大脑改组合并在分叉中成立 | 新的组合节点 |
| 现有节点都不行，但内核原语足以写出新叶子 | 叶子缺口 | 大脑写变体叶子并在分叉中成立 | 离线分诊或外部作者补写，`origin` 记为 `triage` / `external_author` |
| 失败节点的入口本身不可达（评价器试跑也失败） | 上游归因 | 改从上游节点恢复（§2.1.1 第 1 步，满足启用条件后） | 缺口记到上游节点，原始口径仍保留在分母中 |
| 变体执行后本节点 `post` 成立，任务在下游失败 | 失败下移 | 继续从下游节点恢复 | 下游节点的候选优先分到证据门预算（§2.1.3） |
| 感知或语义类键的变体出现位移特征（§2.1.2 触发） | 表达缺口 | 关闭期内该键不写同契约变体，只走 `search` 与改组合 | 改契约或拆分节点交给组合；需新原语或新感知模型类别时转内核缺口；分诊和外部作者不补该键的变体 |
| 完成与否判断错误，或者评价器与保护规则口径冲突 | 判定缺口 | 大脑不处理，只记录 | 补监测谓词；涉及评价器口径的属于内核，由人登记新版本 |
| 内核原语、身体或评价器不足以完成 | 内核缺口 | 大脑不处理，只记录 | 下一个 K 版本，在实验系列之间做 |

**兜底的离线分诊**：针对缺口记录，从失败步骤的快照分叉，把图中契约相同的节点机械地逐个试一遍，再决定交给哪一栏。它的产出 `origin = triage`，不算作大脑自己长出的能力。
