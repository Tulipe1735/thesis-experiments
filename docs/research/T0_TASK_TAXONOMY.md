## 2. 分类原则：范围、目的、技能、评测变化分开

以下结构仅组织应用任务层。用户已明确研究主干是身体熟悉过程，因此不再把这张目的分类树放在身体能力与技能积累之前：

```text
空间范围：T0 单房间
  L0：任务目的大类，例如整理与收纳
    L1：目的子类，例如分类归位
      任务模板：把指定类别的对象放入指定收纳区
        任务实例：模板 + 具体资产 + 初态 + 目标 + seed

独立标签：动作技能、记忆类型、时序结构、泛化变化、物理能力需求
```

借鉴来源：RoboCasa365 的 category / activity / task 层级、BEHAVIOR 的活动与逻辑规格。**下表是本项目适配办公室、会议空间和茶水间后的综合分类，不是任何论文的官方原表。** 原生分类与版本差异见[参考文档](BENCHMARK_AND_MEMORY_REFERENCES.md)。

归类规则：以任务最终用途为主类，以辅助步骤为标签。例如，“把杯子拿给指定接收位置”是物品递送；“为茶歇备好杯子”是饮品服务；“用后把杯子收回”是收纳归位。它们即使共享抓取和放置，也不因此是同一目的；反过来，换一句用途描述也不自动构成新的操控能力。

同一模板只有一个主分类，可以有辅助用途标签。若一个目标确实跨多个目的，使用组合模板并记录子目标图，而不是复制计数。

## 3. L0 / L1 详细目录：8 个大类、44 个子类

来源缩写：RC = RoboCasa / RoboCasa365；B = BEHAVIOR；A = ALFRED / ALFWorld。以下例子均为**本项目拟议任务**，不是对来源 benchmark 任务名的逐字引用。

阶段建议：**近程**表示与当前抓杯底座较接近，仍不保证已实现；**扩展**表示需要新增物体、控制、感知或验收；**远期**表示额外状态模拟、工具或交互成本较大。阶段不是用户已确认的承诺。

### L0-01 物品获取与递送

参考：RC Serving 的递送结构、B 室内物品活动、A Pick & Place 的任务形式。关注“把哪个对象取得或送到哪里”，不混入具体服务用途。

| L1 编号 | 子类 | 具体任务例子 | 资产 / 可验收目标示意 | 阶段 |
|---|---|---|---|---|
| 01.01 | 指定物品取用 | 取起桌面指定杯并稳持 | 单个动态杯；指定对象被持有且离台稳定 | 近程；已有受限抓杯基线 |
| 01.02 | 多候选目标取用 | 从两个不同杯子中取指定一个 | 多个动态对象；目标正确且其他对象未误取 | 扩展 |
| 01.03 | 遮挡或容器内取物 | 打开柜门后取出指定物品 | 可交互柜门、容器、物体；取得目标 | 扩展 |
| 01.04 | 指定地点递送 | 把物品送到同房间接收区 | 源区 / 接收区；物品稳定到位、手释放 | 近程候选；尚缺完整放置链 |
| 01.05 | 多物品集中取送 | 把清单中的两件物品送到目标台面 | 多物体；清单完整、无多取漏取 | 扩展 |
| 01.06 | 受约束递送 | 搬运时保持容器直立并避开禁放区 | 姿态 / 路径约束；过程和终态同时合格 | 扩展；流体约束另计 |

## 4. 独立的基础动作 / 躯体练习表

下表不是 L0 主树。它服务于“熟悉躯体”和跨目的任务的技能复用；不能因有代码接口就声称 agent 已学会对应动作。

| 技能标签 | 行为单元 | 来源 / 用途 |
|---|---|---|
| K01 | 抓取、移送、放置与释放 | RC Pick and Place；当前主要底座 |
| K02 | 开关门 | RC Opening and Closing Doors |
| K03 | 开关抽屉 | RC Opening and Closing Drawers |
| K04 | 旋转旋钮 | RC Twisting Knobs |
| K05 | 操作拨杆 | RC Turning Levers |
| K06 | 按按钮 | RC Pressing Buttons |
| K07 | 插接 | RC Insertion |

| K11 | 接触式推移、擦拭等工具操作 | 项目扩展；不同接触模式需分别验证 |
| K12 | 双手交接与协同持物 | 项目扩展；不因双手机器人外形而视为已支持 |

“躯体练习”可作为独立能力探针集合：姿态可达范围、关节目标与末端变化、接近稳定性、合指与对向接触、负载稳持、释放与退出。每项必须注明动作接口、观测、约束、证据和未知范围。**它们可以为任务提供经验，但不应与生活目的分类混层。**

## 5. 每个任务模板还需哪些标签

| 轴 | 建议标签或字段 | 参考 / 防止的混淆 |
|---|---|---|
| 空间 | 单工作面 / 同房间多功能位 / 是否需要移动 | T0 不自动意味着不移动 |
| 技能 | K01–K12，可多选，另存调用顺序或依赖图 | 技能不是生活任务大类 |
| 时序 | 单目标 / 多目标 / 前置依赖 / 条件分支 / 恢复 | 长程不等于某个固定 L0 |
| 经验复用 | 无历史 / 原始回合检索 / 抽象经验 / 可执行技能 | 区分 memory 与 skill 的贡献 |
| 回合内记忆 | 是否需记住已完成步骤或暂不可见状态 | 与跨回合经验复用分开 |
| 泛化 | 布局 / 对象实例 / 目标关系 / 技能组合 / 房间 | LIBERO 的受控变化思想 |
| 鲁棒性 | 相机、初始机器人状态、语言、光照、纹理、传感噪声 | LIBERO-Plus；不等于新增语义任务 |
| 物理需求 | 刚体 / 关节器具 / 柔性体 / 流体 / 温度或清洁状态 | 外观资产不等于可交互资产 |
| 监督 | 策略可见信息、验收信息、标注是否来自真值 | 防止把特权标签当视觉自主发现 |
| 成熟度 | 资产存在 / 物理可交互 / 机器人可执行 / 独立验收 | 四项分别记录，不能一个“支持”代替 |

注意：当前全可见单杯抓取可以测“经验是否帮助”，但不是必须依赖记忆才能完成的任务。

## 6. 如何从分类得到可执行任务，而非仅得到名字

建议模板至少包括：主分类、自然语言目标、角色化对象、资产能力要求、功能区、初态谓词、目标谓词、过程约束、允许观测、动作接口、预算、失败类型、独立验收器、版本与数据划分。

流程与原文一致，但补上验收和数据隔离：

1. 人工挑选 L1，写任务模板及“什么才算成功”。
2. 定义所需资产能力、功能区与初态 / 目标谓词；不要先随意堆资产。
3. 在受约束区域内按 seed 选择对象和初态；保存实际采样结果，不只保存 seed。
4. 检查穿模、稳定性、可达 / 可交互性与非平凡性；必要时验证存在参考解。
5. 区分无效实例与策略执行失败：生成器拒绝率、参考解覆盖率和 agent 成功率分别报告。
6. 按实例族冻结练习、开发、留出测试集；对外宣称的泛化轴必须真的留出。

候选谓词如 `On`、`Inside`、`Open`、`HeldLifted`、`Stable` 仅示意语义，不是已统一实现的 API。某个物体“在容器内”的几何定义、时长阈值、接触条件都需要独立规格。

这不是缩减完整分类，而是把“分类覆盖”与“现在可执行”分开。这些是身体练习后的应用测试候选，不意味着直接调用现成抓取工具就是研究起点；身体练习顺序见[新主干](BODY_TO_TASK_TREE.md)。

- `SupportedIn` 要求完整杯底或水果投影进入容器内侧，至少留 1 mm 余量；容器底板实际向上支撑力达到该对象重量的 25%，底部高度误差不超过 4 mm。边沿或桌面接触不能代替底板支撑。

- 检查间隔为 50 ms；缺对象、缺接触或关节数据不能默认通过，时间乱序拒绝，采样缺口不能拼成稳定窗口；带全程留盘约束的轨迹出现缺口也不能通过。有限采样不等于对采样间每一时刻的数学保证。

这套新资产谓词目前用于生成与反例检查。正式机器人成功还需要有效初态、完整实际执行轨迹、机器人倾斜/位移保护、无外力或绑物约束以及无执行异常；仅检查场景不具备这些机器人证据，`verified_task_success` 为 false。既有 T01/T03 的冻结验收器与正式 Skill 适用范围继续按原登记解释。

资产沿用上一节的 13 个桌面原型，排除货架和柜体。每个原型生成 3 个训练参数实例、2 个测试保留实例，共 **39 个训练候选、26 个保留候选**。半径、高度、完整保守投影、容器底板/边沿和质量实际变化；质量按尺度三次方调整。杯/果/瓶/非目标物的训练尺度为 0.98/1.00/1.02、保留尺度为 0.95/1.05；容器训练尺度为 1.04/1.06/1.08、保留尺度为 1.02/1.10，逐例检查容量。带把杯的保守投影另覆盖固定把手厚度。外部瓶的本地适配器同步缩放原 mesh 和底部偏移，并绑定声明颜色；原始文件保持不变。

这些是**本批训练未出现的新参数资产实例，基础几何族共享**，不是新的扫描资产、未见语义类别或整个研究历史中未知的对象。实际使用哪些实例由两个 manifest 和 `split_audit.json` 记录，不把注册候选数量当作实际覆盖数。

桌面源位置定义 18 个带 ±12 mm 抖动的单元，12 个分给训练位置池、6 个保留给位置测试；训练/测试单元的中心采样范围至少间隔 131 mm。容器间转移另外定义源容器局部坐标中的 6 个带 ±4 mm 抖动单元，4 个训练、2 个测试，范围至少间隔 24 mm。容器位姿和目标区域在预定合法范围内随机；位置留出针对源位置单元，不宣称目标区域也采用全空间留出。

先按模板分层，再按资产池和位置池生成四组：

| 分组 | 每模板 | 总数 | 资产池 | 源位置池 |
|---|---:|---:|---|---|
| `train` | 32 | **256** | 训练实例 | 训练单元 |
| `test_position` | 8 | 64 | 训练中已出现的实例 | 留出单元 |
| `test_asset` | 4 | 32 | 保留参数实例 | 训练单元 |
| `test_joint` | 4 | 32 | 保留参数实例 | 留出单元 |
| 测试合计 | 16 | **128** | 分轴报告 | 分轴报告 |

训练 seed 为 50000–50255，测试为 60000–60127；此前 31000–31009、1300–1303 及其他开发记录不重新命名为测试。每个实例的候选位置、几何拒绝和最终参数全部保存；位置提议最多 96 次，拒绝原因仅为几何初态约束，不依据机器人成功率。组标识按模板、对象资产及位置单元计算，抖动或改名不会使同组跨训练/测试；实际参数再作独立重复检查。

这里的 32/16 是首批工程覆盖规模，不是统计功效计算或可靠性保证。两边都包含八个模板，因此评估的是同一拿放家族中新的位置/参数资产组合，不能称为未见任务模板泛化；三个测试轴也不是同一物理初态配对的因果实验。

### 12.3 文件、冻结与后续训练入口

数据根：`experiments/t0_agent_v1/tabletop_dataset_20261026_002/`。

- `train/manifest.json`：256 个允许练习并更新 Skill/Memory 的任务及固定随机顺序。
- `test/manifest.json`：128 个仅用于产物冻结后评测的任务，带上述三个测试轴标签。
- `train/instances/<id>/task.json`、`test/instances/<id>/task.json`：公开任务目标、对象角色和观察接口；不含初始 xyz、质量/尺寸、qpos/qvel、接触真值或容器容量示例。
- 同例 `instance.json`、`qualification.xml`、`initial_state.json`：场景构造/验收专用资产、完整实际采样与静置状态，包含原始/接受初态的 qpos/qvel 和支撑快照；不作为策略观察。
- `templates.json`、`assets.json`、`position_cells.json`、`split_audit.json`、`results.json`：模板、资产、位置划分、隔离审计与汇总。
- `frozen_sources/` 与 `freeze_manifest.json`：六个相关模块的源码快照和全部核心文件 SHA-256。每个文件、目录排他创建；不复制 `.mjb`、原始轨迹或传感器大文件。

训练入口 `load_training_tasks(dataset)` 先验证冻结的训练 manifest，再按已登记的随机顺序读取其公开任务，并拒绝跨到测试目录的指针。测试文件仍在同一工作区，当前是有记录的工作流边界，不是操作系统权限隔离。未来训练 Agent 应只加载该训练入口；场景初始化与独立验收通过获准工具处理私有初态。测试应在统一 Skill/Memory 冻结后运行，不依据测试反馈修订后仍沿用同一份未见测试口径。

八个训练示例各有一份引用原 G1 / 香港房间资源的 `pantry_G1.xml`，只完成编译。机器人初态继续引用原只读 `grasp_optimization/episodes/final_reference_1000/initial_state.npz`，哈希和按机器人关节名称转移的规则写在预登记中；新物体初态使用各实例自己的记录。现有 `PilotRobot` 依赖固定对象名称，尚未直接接入此任务集；G1 可达性、感知、扫掠路径和训练运行器仍需按后续任务实现，不把检查场景静置等同于机器人可执行性。

### 12.4 初态检查与范围

最终批次 `tabletop_dataset_20261026_002/results.json` 记录 **384/384 检查场景初态通过**：训练 256、位置测试 64、资产测试 32、联合测试 32；八份原场景模型编译通过。每例固定推进 2 s，最后 1 s 检查声明支撑和稳定；原始与静置末态检查明显穿插，末态目标须尚未满足。TP08 由源容器实际承托。机器人任务执行、统一 Skill 生成和测试策略反馈均为 0。

12 项新检查涵盖数量/分层、确定性、位置范围间隔、改名不能隐藏同组泄漏、资产 ID 与物理参数一致性、公开任务不含私有初态、训练入口拒绝跨集读取和篡改、八模板两种资产池的真实物理初态、容器转移初态、稳持反例及外部瓶缩放/颜色。完整交付审计与测试日志保存在 `experiments/t0_agent_v1/tabletop_dataset_audit_20261026_001/verification.json`，不改写已冻结的核心数据文件。

交付的 16 项审计全部通过，1,942 个冻结文件的哈希一致，训练和测试没有 seed、整组或完整物理初态重复。训练实际使用 39 个资产实例；资产/联合测试实际使用 23 个保留实例（26 个保留候选中另 3 个未被固定清单选中），位置测试使用 37 个训练已见实例。全部接受初态仍位于所属位置单元内，最小边界余量为约 3.76 μm；没有通过静置漂移串入另一分区。

首批 `tabletop_dataset_20261026_001/` 同样保留，不将其数据混入最终训练或测试。最终版只补齐外部瓶的声明颜色和渲染几何属性一致性、外部来源哈希检查；采用相同随机命名空间、固定清单与物理门槛，没有通过换 seed 补抽筛选成功。检查通过表示可复现任务初态，不是专家轨迹、Agent 学习效果、G1 完成率或实体证据。

本节划分流程使用 experimental-design 1.5 的分层、整组隔离和预登记思路；未安装其未使用的 DOE 包装器依赖。软件流程参考已核实为 Kassis, T., Agarwal, V., He, Y., Patel, D., & Brueckner, A. M.
