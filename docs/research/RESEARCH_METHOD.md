# 科研方法：怎样设计、执行和报告一轮实验

日期：2026-11-08。状态：现行方法，给接手的 agent（Codex 等）用。边界：MuJoCo 仿真，不涉及实体机器人。

本页只讲做法。研究主张和晋升规则以 `GROW_UP_MINIMAL_EXPERIMENT.md` 为准，术语以 `../../GLOSSARY.md` 为准。示范用的实例是 T02 v3：配置在 `experiments/grow_up_harness_v2/configs/grow_t02_v3.json`，运行结果在 `experiments/grow_up_harness_v2/runs/grow_t02_v3_20261107_001/`，报告在 `T02_GROW_V2_20261107.md`。要模仿就照这三份写。

## 1. 先把问题落成一个可证伪的比较

动手前写清楚下面四点，写不出来就先别跑：

1. **单一问题**：这一轮只回答一件事。例子：在同一个失败初态上，给了人工诊断的 SLOW 能不能修好工程组合修不好的一段？
2. **处理臂与对照臂**：两臂只有一个因素不同。没法做到单因素时，报告里要写明混入的是哪些因素，结论也降成"配对"等级，不写"收益"。
3. **测量**：只用独立评价器读落盘状态得到的 `verdict.json`。不用模型自评，不用在线 world 上的判断。
4. **结论上限**：先写好"这一轮最多能说什么"。T02 v3 的上限是"一次带人工诊断的 Agent 成功"，不是"自主发现"。

## 2. 基线族：开跑前登记，缺一项就不算对照实验

每个带对照的运行都要在 `registration.json` 的 `baselines` 里登记下面这些：

| 角色 | 作用 | 判废规则 |
| --- | --- | --- |
| 负对照（如 wait、空操作） | 证明评价器不会白给成功 | 负对照被判成功，**整批作废** |
| 正例对照（工程参照或回放） | 证明这个初态可达、评价器能判对 | 正例没复现成功，这个初态**不进练习**，跳过并记录，不补抽 |
| 原失败 / fallback | 处理臂要打败的对象 | 必须在同一保存初态上复现原失败 |
| 处理臂 | 待验证的 agent / skill / memory | — |
| 从零组（可选） | 同样任务、空库，用来看库的作用 | 0 次进入物理回合时，只能报"接口未通过"，不能报"库更好" |

初态以文件形式保存（`sampled_initials/*.npz` 加上实际采样出的对象、位姿、朝向、参数），只存 seed 不算数。消耗过的 seed 写进配置里的 `consumed_dev_seeds`，之后不再当作未见过的初态。

## 3. 预测与证伪条件写在配置里，跑完不改

配置里的 `prediction` 和 `falsification` 字段要在开跑前写好：

- 每个关键臂写一句期望结果，带上数字（例如"留出至少 1/2 由 FAST 解出"）。
- 写清什么结果会推翻这个预测。
- 不确定就直说概率（"大约一半一半"），不要写成能永远成立的模糊话。

跑完之后，先逐条对照预测再解释结果，分成四类：成立、被推翻、未能检验、预测里没想到的。预测原文一个字都不改。

## 4. 预算与停止条件

- 每回合仿真时长、命令数、提议次数、模型耗时的上限都写进配置的 `caps`，运行中途不改。
- 遇到下面任一情况就停，写成失败记录，不想办法绕过去：负对照成功；评价器复算不一致；沙箱（seccomp Worker）建不起来；网关不可用时用脚本冒充 Agent；必须改评价器、安全限制、预算或 test split 才能通过。
- 为了跑通而改的常量或流程，在报告里单独列为"本轮自主决定（变更后结果）"，不和原配方的结果合并。

## 5. 执行（2026-11-11 精简）

源码、库、证据分开。当前命令只维护在 [harness 入口说明](../../experiments/grow_up_harness_v2/README.md)，不在本页重复一整套命令。

- 日常编辑 `library/` 的 leaf/组合或 `harness/artifact_mapping.py`。显式 `artifacts.py freeze` 时才固定所选程序及其真实依赖，生成一个可移动的 JSON 包；不冻结整仓路径，不复制整库，不追着谱系父运行检查源码。
- 新实验仍用新配置和排他创建的新输出目录。新输出统一进仓库根 `outputs/`。旧 `runs/`、`validation/` 与已完成记录保持只读。
- T03 只用 `calibration/t03.py`：prepare（自动焦点门）、propose、train、evaluate、execute、card、report。不为每轮、每个 leaf 或每次修订新增一支脚本。
- 一个运行保留 `config.json`、`registration.json`、所用小包 `artifacts.json`、实际采样初态、事件和逐任务结果/独立 verdict。候选原始回复与拒绝保存在 `proposals/`；不自动写重复源码快照、投影目录、ledger 冻结清单和摘要文档。
- 同一 code/skill 绑定使用相同工件、实际初态与预算；本地 ID 调用如实标记，不冒充模型自主选用。负对照仍执行，失败不筛掉。完整训练成功之前不生成、不执行新留出。
- 冻结包内容不可更改；修改 leaf 或映射后需要新包时冻结一次、新登记。正常运行复用已有包与检查结果。额外哈希复算、`artifacts.py verify` 只在用户明确要求审计时执行。
- runtime/evaluator 记录声明的接口版本；工件包不等于冻结整个软件环境。实现改变须更改版本，变更后结果分开报告，不能仅凭版本标签声称所有运行代码逐字一致。
- 代码变更按风险做相关检查；整套检查已通过且代码未变时复用证据，不把全量单测或整仓审计当作每次 run 的重复前置动作。
- 成本仍分提议、诊断、接口拦截、物理回合、Worker、命令、仿真秒数与模型耗时；报告只使用已记录的计数，不补造缺失项。

## 6. 成功分两栏报告

| 栏 | 含义 | 当前例子 |
| --- | --- | --- |
| 工程参照成功 | 人写的配方或回放跑通，且独立评价器判成功 | T02 v2：3/3 未见初态 |
| Agent 成功 | Agent 写的 op 或 skill 在同一评价器、同一保存初态上跑通 | T02 v3：1 例，带人工诊断提示 |

Agent 成功还要标出带了哪些辅助：人工诊断、真值分析、录制段占比。T02 v3 的六段里有五段是录制回放，新代码只替换了撤手那一段。

## 7. 结果反馈与按需报告

日常完成后只在聊天中简短说明结果、实际验证及必要的阻塞/边界，不默认新建报告，也不附固定的验收问题。原始初态、日志、结果与 verdict 照常保留。

仅在用户明确要求报告时，新报告放在 `docs/research/<TOPIC>_<yyyymmdd>.md`，首段三行内写清日期、状态、边界。之后按这个顺序写：

1. **结论**：一两句，带上栏名和分母。
2. **结果表**：组 / 任务 / 结果 / 证据路径（路径相对本目录根，指向 `verdict.json` 或 `result.json`）。
3. **成本**：照搬 `summary.json` 的 `counts`。
4. **预测对照**：按第 3 节的四类写。
5. **证明了什么、没证明什么**：每一条"没证明"都要具体，能让下一轮直接拿来设计对照。
6. **本轮自主决定**：阈值、容差、初态、种子范围、跳过项、重试、模型选择。
7. **未决问题**：每条都写成下一轮能执行的对照。

## 8. 定稿前找反例

会改变研究方向的结论（例如"库比从零更好""Agent 自己发现了修法"），定稿前要开一个新 context 的 subagent，**只给它文件路径，不给结论**，让它按严重程度列反例。依据反例收窄结论，在聊天中简述；用户已要求报告时再将反例追加其中，不为审查另建报告。常见反例模式：

- FAST 遇到首个成功就停，新旧工件实际没有并跑，增益没法归因。
- 修复方向来自人工或真值诊断，模型只是照着提示实现。
- 新代码在整条链里占比很小，成功主要来自录制段。
- 留出半径和训练半径不一样，或者留出 n 太小。
- 训练任务是按失败挑出来的，挑法要登记。

## 9. 当前的方法缺口（下一轮优先做）

这几条直接来自 T02 v3 的未决问题：

1. 去掉人工诊断，只给逐杯反馈和诊断模型，看 Agent 能不能自己定位撤手推杯。这组对照用来区分"按提示修复"和"自己发现"。
2. 关闭"FAST 首个成功即停"，在同一个留出任务上并跑新旧组合，用来判断新工件对留出的贡献。
3. 抖动阶梯扩大到 10 mm 以上（要先放宽生成器上限），找出开环回放在哪里失效。这也是让 SLOW 真正打开的前提。

## 10. T03 持续训练与留出开启规则（2026-11-10，用户明确修订）

本节适用于 T03 后续训练，优先于本文件第2节“正例对照失败，该初态不进练习”的任务级排除规则；原运行与原配置不追改。

- 合法但执行失败的工件仍保留源码、冻结包、失败判定、来源与修订谱系，保持 candidate / 未验证。现行工件从 library 显式冻结，失败与无效原始回复留在运行证据中；历史 Store 不改写。不只保留成功版本，不让失败候选冒充 FAST 已验证能力。
- 完整参考程序失败是诊断起点，不自动禁止该任务的 SLOW 物理修复，也不停止其他训练任务。仍须确认评价器、原子执行接口与保护有效；系统性接口、评价或执行隔离问题必须停止相应路径。
- 生成器按预登记的连续任务流分块生成训练任务，保留全部采样、合法性拒绝、策略失败与修订。不得事后筛成只含成功的任务集；需要改变课程范围时，在新配置与新运行中明确登记，分别报告变更前后结果。
- 训练至少取得一项由独立评价器判定的**完整 T03 成功**后，才允许锁定最终工件并开启新留出评测。几何可达、抓起、数值检查通过、工程脚本或调用成功不能替代所声明的 Agent 训练成功。
- 零成功时继续生成训练任务、诊断与有界修复，不把留出测试用作下一步诊断。每个执行阶段仍有硬预算；预算耗尽记为训练检查点，留出门保持关闭，后续训练须承接完整失败与工件库，另行登记下一预算段。
- “直到首次成功”的训练统计必须同时给出已生成任务、已尝试任务和全部回合的分母；此停止规则带来选择效应，训练发现率不能当作独立评测成功率。
- 已经执行过策略或用于诊断的旧留出任务保持已消耗身份。后续冻结评测使用新登记且未参与优化的任务；零训练成功的旧留出结果保留，只能作为原流程执行事实，不能补称新规则下的有效泛化验证。

## 11. 注意力预算：让下一轮的焦点可执行（2026-11-11）

适用于 T03 及之后的所有续轮。它约束的是"这一轮该把回合花在哪"，不改变评价器、保护或成功口径。

**一轮可以同时推进多个阶段**，但每个阶段都必须单独可归因。开跑前写进配置：

```json
{
  "focuses": [
    {"stage": "locate",         "mechanism_trigger": "主定位球面拟合置信不足，残差共识带被触发"},
    {"stage": "preflight",      "mechanism_trigger": "默认路线被净空筛选拒绝，返回替代位姿或 null"},
    {"stage": "close_and_test", "mechanism_trigger": "闭手前拇指-手指对齐超阈值，或 grip_settle 触发保护"}
  ],
  "focus_cap": 3,
  "handoff": {
    "approach": ["closed_hand_clearance_at_arrival", "retreat_path_clearance_at_arrival"],
    "close_and_test": ["thumb_finger_alignment_at_arrival", "grip_settle_force_window"]
  }
}
```

- `stage` 只能取 `harness/t03_handoff.py` 的 `STAGES`，顺序与 `t03_runtime.py` 的执行循环一致。
- 每个焦点必须有自己的 `mechanism_trigger`，且是可观测条件。默认路径跑通不算触发。
- `handoff` 要覆盖到最深一个焦点为止的每个已设关卡阶段。没写等于没声明，`validate_registration` 返回不通过。
- `focus_cap` 默认 3。再多就分两轮，因为回合数和归因能力都是有限的。

**不在 `focuses` 里的阶段本轮不改**，但可以诊断、可以在报告里列为阻塞项。上游阶段挡住的回合，既不给下游工件记功，也不记过。

**结果按阶段分别报**：每个焦点各自"触发几次、触发后完整成功几次"。不合并成一个总数，也不拿整体成功率代替。

**换/加焦点的信号**（满足任一，继续扩同一工件不会产生新信息）：

1. 某阶段连续两轮触发数为 0；
2. 触发后完整成功为 0，且失败已挪到该阶段下游；
3. code/skill 连续两轮同成功率、同断点。

**工具**（只读，不重跑物理、不写回运行目录）：

```bash
cd ~/projects/thesis-experiments/experiments/grow_up_harness_v2
python -B calibration/t03_focus.py precheck <新配置> --previous runs/<上一轮>   # 门，不通过 exit 2
python -B calibration/t03_focus.py report runs/<run>                          # 焦点卡
python -B calibration/t03_focus.py report runs/<run> --config <新配置> --packet # 作者 packet
```
