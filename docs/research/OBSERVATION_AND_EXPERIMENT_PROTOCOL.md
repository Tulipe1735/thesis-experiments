## 2. 图片约定与本地实际实现的差异

只读核对结果：

- 身体资料实际包含 43 个驱动关节：29 个身体关节和双手各 7；单侧臂手为 7 臂 + 7 手 = 14。
- 当前 `fk(side)` 读取当前身体的掌位和姿态，不接受任意假设关节配置作为参数。
- 图片称 `set_joints()` 主要返回关节角、`move_ee()` 含 `actual_palm`；当前代码正常 `set_joints()` 返回 `status/time/palms`，跟踪异常时才附完整 `state`。`move_ee()` 没有该图片所示 `actual_palm` 字段，而是在返回中附 IK / 位置误差信息。

- 现有保护包括关节 / 跟踪 / 力矩 / 底座 / 预算等检查，但不是完整自碰撞与环境碰撞保证；身体试探需要另行验证安全包络。

## 3. 初始资料、经验与技能的来源必须分开

| 来源 | 例子 | 如何报告 |
|---|---|---|
| 初始已提供资料 | 关节轴、连杆长度、坐标系、机械限值 | 所有对照组共享，不算学习成果 |
| 从资料推导 | 根据已知几何预测一个关节小动作的方向 | 标为解析 / 推理所得，不伪称由试探发现 |
| 实际交互记录 | 请求动作、实际角度、掌位、延迟、接触、保护触发 | 保留成功失败和限幅；与推导分开 |
| 经验提炼 | 某姿态下的执行误差、接触规律、恢复条件 | 关联原始证据和适用范围，避免无依据普遍化 |
| 程序生成 | 根据允许资料和经验形成的闭环关节控制程序 | 区分资料驱动与经验驱动成分，独立验证迁移 |

给出完整几何后，模型可能不做很多试探就推导部分运动规律。这不是违规，但意味着不能把“程序能运行”本身归因于经验。基线应允许同样的身体资料、传感器、推理和程序生成预算，区别在是否有过去交互经验可复用。

本期不提供现成 `move_ee()` / IK 或任务级抓取程序。用户已明确允许 Agent 用 Prompt 几何、白名单公开 API 和自身反馈自主编写、调试和改进 IK / 运动学求解程序，最终仍经关节接口执行。区分知识驱动 Skill Synthesis 与经验驱动 Skill Improvement；两者均属 Grow Up，不把初始知识构建能力误报为练习收益。身体资料权限不包括整个仿真世界、任务真值或工程教师轨迹。

## 4. 已确认的人机分工

- 人工定义任务 / 练习目标、环境、可用接口、安全约束和独立验收。
- Agent 自己选试探动作，提炼 memory，生成 skill 程序。
- 人工检查安全和证据不等于代写动作规律；若人为修改动作或生成程序，必须单列为人工辅助条件。
- Skill 与 agent 在线试探使用同一传感和动作白名单，不能通过普通代码调用绕过限制。
- 练习阶段对自产程序的调试、改进已由用户明确允许；Candidate 可经同一保存初态的有/无 Skill 配对显示改善后按 `paired` 入库，也可在完整保留失败、合法诊断、有界修复并完成同初态脚本/agent 双复验后按 `repair_lineage` 入库。跨 seed 是扩大适用范围的后续验证。不扩大为修改 agent 框架、评价规则、权限、root down 或元策略递归优化。

## 5. 推荐最小课程：不要求先全身毕业

| 顺序 | 身体练习 / 应用目标 | 验收重点 | 当前状态 |
|---|---|---|---|
| C1 | 安全小幅关节试探与局部运动 | 请求与实际变化、稳定性、保护记录；不是单独的任务成功成果 | 待建独立入口 |
| C2 | 指定区域内掌位到达与姿态保持 | 对未练习目标 / 起点的到达误差、保持时间、动作成本 | 待建模板与验收 |
| C3 | 接触、合指、轻微试提与稳持 | 对向接触、物体身份、离台与稳定；策略信息与验收真值隔离 | 有工程参照，无自主新技能证据 |
| C4 | 单杯完整取放 / 归位 | 接近、抓持、移动、释放、放稳分别验收，完整结果另计 | 待扩展执行与验收 |

C2 可以直接给本体空间目标，不涉及读取杯子真值；C3 / C4 的物体位置仍需通过允许的视觉 / 深度获得。分阶段复位若使用工程准备姿态，必须标为条件化子技能测试，不能当完整自主接近成功。

## 6. 已确认的验证方向与方案入口

### 6.1 主要收益

用户已确定先同杯型新位置与起始姿态，分开测试；具体首版 P 轴只变杯位，J 轴只变初始关节姿态，朝向和物体变化不混入。C2 到达是诊断，C3 / C4 为应用目标，不能只用运动误差降低就宣布会抓杯。

### 6.2 冻结评测与在线适应分开

用户已确定先练习、冻结 Skill / Memory，再测新实例；回合内闭环反馈不等于长期更新。Online Continual Learning 保留为后续独立实验，另定任务流、预算与重置，不与主结果混报。

### 6.3 公平对照

旧版仅按 memory-only / skill-only 区分不足以分清知识合成和经验改进。新方案采用冻结技能 K（知识合成）/ E（反馈改进）与显式 memory 无 / 有的 2×2 条件；M 同源同版，不传递替代程序，测试不生成或改写技能。K 与 E 同初始 S0，编程预算、版本 / 提交上限匹配，物理反馈可用性不同，成本分别报告。

Candidate 晋升率、`paired` / `repair_lineage` / `expanded` 验证等级、正式库覆盖率、系统成功率与候选诊断分开；不隐藏未晋升成长轨迹。同初态配对只改变候选 Skill 是否可用并被实际调用；修复谱系则明确记录程序变化，因此不能冒充 Skill 单因素配对。若要测 Memory，则冻结 Skill、只改变 Memory 是否可用，不能在一个两回合对照里同时改变两者。具体生命周期、验证指标、控制建议和冻结边界见[整体方案第 5–10 节](GROW_UP_MINIMAL_EXPERIMENT.md)。单个局部验证不承诺统计显著性或跨初态可靠性。
